# Architecture Decision Records (V0)

| # | Decision | Why / alternatives |
|---|---|---|
| 1 | **Modular monolith** (api + worker + web, shared packages) | Future ledger needs transactional consistency; microservices rejected. |
| 2 | **Pooled DB + RLS**, tenant = `organisation_id`, transaction-local `app.organisation_id`/`app.user_id` | Schema/DB-per-tenant rejected (ops cost). Fails closed without context; composite FKs stop cross-tenant references. |
| 3 | **Practice-first single model**: Organisation(PRACTICE\|BUSINESS)→Companies; `company_scope ALL\|ASSIGNED` | Direct business = one-company org. No second product architecture. **Amended by ADR-23/24:** a distinct `practice` level now sits between organisation and company, and access is granted at organisation, practice and company level. |
| 4 | **Prisma 6** + hand-written SQL appended to migrations (RLS, grants, triggers, exclusion constraint, seed) | Prisma 7/8 not adopted (driver-adapter churn, release candidates). Schema is source of truth; custom SQL is documented drift. |
| 5 | **Opaque server-side sessions** (hashed, idle+absolute expiry), not JWT | Instant revocation, no key rotation; works unchanged with future OIDC logins because providers only prove identity. |
| 6 | **IdentityProvider interface**; lockout/MFA/session policy applied by `AuthService` for every provider | Entra/Google/Auth0 = one new class + `user_identity` row. |
| 7 | **TOTP implemented in-house** (RFC 6238, tested against RFC vectors), secrets AES-256-GCM, replay protection, recovery codes | Avoids a dependency for ~40 lines; MFA type is an enum, so WebAuthn adds a verifier, not a flow change. |
| 8 | **BullMQ + `job_record`** as durable source of truth + sweeper | Redis may lose data; Postgres record lets us re-dispatch. Sensitive payloads encrypted in Redis and Postgres. |
| 9 | **Ports/adapters** for storage, email, antivirus, identity. AWS knowledge only in `createStorage/createEmail` and Terraform | Moving cloud or adding DR changes env vars, not code. |
| 10 | **Residency guard** in app config and Terraform (`allowed_regions`) | Production refuses to boot outside approved regions; DR region must also be approved. |
| 11 | **Audit append-only in DB** (grants + triggers), written in the business transaction | Cannot be altered by the app role or the owner without disabling triggers. |
| 12 | **Vitest everywhere**; Playwright *library* inside Vitest for E2E | One runner. Integration files run serially (shared DB/Redis). |
| 13 | Turborepo dropped; `pnpm -r` topological build | Not needed at this size. |
| 14 | **OpenAPI in V0**: contract generated from the running Nest app; request schemas ARE the runtime zod validators; route docs table enforced complete by tests; spec committed and drift-checked | Contract is a first-class asset. |
| 15 | **Transactional outbox in V0**: event row written in the business transaction; polling relay with `SKIP LOCKED`; BullMQ hand-off; consumer idempotency via `event_consumption` in the consumer's transaction | Guarantees no lost/phantom events; at-least-once delivery, exactly-once effect. |
| 16 | **Layered login throttling** (IP+account pair, IP, account-under-attack with trusted-IP carve-out) replaces per-account lockout | Stops brute force without enabling lockout DoS; no account enumeration. |
| 17 | **Auth tables outside tenant RLS** is a documented, tested exception (`security-architecture.md` §1.1) | RLS there adds complexity/failure modes with no isolation benefit. |
| 18 | **Real-infrastructure test layer**: shared adapter contract suites run against fakes and real S3/ClamAV; CI requires them (`INFRA_REQUIRED=1`); S3 protocol via moto (MinIO no longer distributed), ClamAV via the official image | Fakes cannot drift from reality. |
| 19 | **Workflow engine, tasks, notifications, integration + AI abstractions** are V0 foundations; AI output is proposal-only behind a human-approval workflow | Reusable by V1+ without re-implementing approvals or leaking vendor SDKs. |
| 20 | Migrations non-destructive by default; destructive ones need an approval marker + verified backup id | `docs/runbooks/migrations.md`. |
| 21 | Deferred: SSO providers, WebAuthn, outbox retention/cleanup job, Redis-backed edge rate limits | Not needed for V0. |
| 22 | **Naming convention** (one, before V1): singular snake_case tables; `<entity>_id` columns; join/grant tables are named for their level - `organisation_membership`, `practice_membership`, `company_membership`; constraints/indexes `<table>_<columns>_fkey\|key\|idx`. Renamed only the ambiguous tables (`membership`, `company_assignment`); **pluralising every table was rejected** (touches ~30 tables, policies, FKs and tests for no functional gain) | Specification table list uses plural names; functionally equivalent. Renames are metadata-only `ALTER ... RENAME` (data, RLS, grants, FKs preserved), flagged by the migration-safety test and approved with a backup-required marker. |
| 23 | **Practice is a distinct entity under Organisation**, not a specialised/nested Organisation. Canonical ownership: `organisation` owns and bills; `company.organisation_id` is the owner, `company.practice_id` the managing practice (required for PRACTICE organisations, forbidden for BUSINESS, enforced by trigger + composite FK); `organisation.type` is immutable. | One tenant boundary (RLS, outbox, audit unchanged); no cross-tenant relationships; direct businesses need no pretend practice; multiple practices per organisation supported; cross-organisation engagements can be added later as an explicit grant table without changing the hierarchy. See `v0-hierarchy-and-authorisation-design.md`. |
| 24 | **Layered authorisation with one central authoriser**: platform role (no tenant access) -> organisation membership (role + reach) -> practice membership -> company membership. Permissions have a scope (ORG/PRACTICE/COMPANY); for a company the most specific grant wins and replaces broader ones (can restrict or extend); deny by default; anti-escalation at every level. Implemented once as pure functions in `@uk/contracts/authz` + `AccessContext` in the API; an architecture test forbids services re-implementing role/scope logic. | Least privilege and testability; avoids per-controller drift. Trade-off: "replace, not union" means a company grant can lower access - intended and documented. |
| 25 | **Reusable workflow foundation**: versioned definitions (`standard_workflow` DRAFT->IN_PROGRESS->REVIEW->APPROVAL->COMPLETED/REJECTED + `generic_approval` maker/checker); per-transition permission evaluated for the instance's company; segregation of duties across ALL attempts; mandatory comments/evidence per transition; explicit reassignment and reopen (retry); **a database trigger refuses any state change without a recorded transition in the same transaction**. Stricter (accounting/statutory) workflows only add controls. | "No silent transitions" is enforced below the application, not just by convention. |
| 26 | **AI proposal state model**: `SUGGESTED -> UNDER_REVIEW -> ACCEPTED \| REJECTED` (workflow `ai_proposal_review` v2), provenance persisted (provider, model, prompt version, confidence, source evidence, run), human decision and *application* recorded separately; `ACCEPTED` applies nothing - the owning service applies it through its own authorised path and calls `recordApplication`. Other AI use cases register their own workflow type. v1 (legacy) instances remain decidable. | AI never posts/files; recommendation and human decision stay distinguishable. |
| 27 | **Migrations must work for a non-superuser owner** (production `uk_migrator`): FORCE RLS applies to table owners, so data statements lift RLS on the specific table for the migration transaction only and restore it. The two earlier seed/UPDATE migrations were corrected (no persistent environment had applied them); a test builds the whole schema as a non-superuser. | Found during this work: previously the seed would have failed (or silently no-op'd) outside CI's superuser. |
| 28 | **`audit:read` is company-scoped** (was organisation-wide). Audit events carry `company_id`; readers see their companies' events plus organisation-level events only if their organisation role holds `audit:read`. Before/after, reason and source workflow added; IP/device capture switchable. | Least privilege per company; completes specification §8. See `v0-tranche-a.md` §2. |
| 29 | **Outbox ordering is per aggregate**, enforced by head-only relay publication + a consumer-side guard; poison events block only their aggregate; cleanup deletes processed events after a retention window and can never delete unprocessed ones. | Strict global ordering would serialise the whole platform; per-aggregate order is what business logic needs. See `v0-tranche-a.md` §3. |
| 30 | **Reference data is a protection class of its own** (`REFERENCE`: global, no `organisation_id`, `SELECT`-only for the runtime role, changed by migrations). Tax jurisdictions are effective-dated with a non-overlap exclusion constraint; companies hold the jurisdiction *code* (a code is not unique over time, so a trigger checks existence rather than a foreign key). Contacts are generic and org-level or company-level; addresses belong to exactly one owner. | Keeps tenant tables and global reference data separable and testable; avoids V1 semantics in V0. See `v0-tranche-a.md` §5. |

## Known limitations (honest list)
- Login volume cap per IP can affect users behind a shared NAT during an attack (pair/IP/account layers otherwise target the attacker only).
- Global auth tables are protected by application-level controls only — see `security-architecture.md` §1.1 (tested).
- Terraform passes `fmt` + `validate` but has not been applied to a real AWS account. The migration runs as a pipeline step (`infra/db/migrate.sh`), deliberately not provisioned as infrastructure.
- Real S3/ClamAV tests run in the `infra` layer (`pnpm test:infra`); locally against a stand-in S3 server and a minimal-signature clamd, in CI against MinIO + official ClamAV.
